# PRD — 레시피 인포그래픽 트랙 · 빵찌 스레드

> **단일 출처(Single Source of Truth).** 빵찌(@bbangjjioo) 계정의 **레시피 콘텐츠 트랙** 전체 규격.
> 기존 쿠파스 꿀템 트랙(`prd-쿠파스.md` · `queue.json` · `coupas-daily.yml`)과 **완전히 분리**된
> 별도 큐·별도 워크플로로 돈다. 포맷·톤·컴플라이언스·도구가 바뀌면 **이 파일만 고친다.**

## 0. 계정 전체 트랙 구성 (2026-08-26 확정)

| 트랙 | 큐 | 워크플로 | 발행 |
|---|---|---|---|
| 요일 주제글 | 없음(`threads_post.py`) | `threads-daily.yml` | 하루 1회 07시 KST |
| **레시피(이 문서)** | `recipe/recipe_queue.json` | `recipe-daily.yml` | **하루 3회 11·15·18시 KST** |
| 꿀템(쿠파스) | `queue.json` | `coupas-daily.yml` | ⛔ **자동발행 중단** — 크론 제거, 수동 실행만 |

- 꿀템은 사용자 결정으로 자동 발행을 껐다. `queue.json` 은 지우지 않았으니
  되살리려면 `coupas-daily.yml` 의 `schedule:` 만 복구하면 된다.
- 레시피 트랙은 위 두 트랙과 **완전히 분리**된 별도 큐·별도 워크플로로 돈다.

## 1. 목적 / 컨셉

- **계정**: 빵찌(@bbangjjioo).
- **페르소나(2026-08-26 확정)**: **30대 초반, 요리가 취미인 여자.**
  - 전문 셰프가 아니라 **집에서 자주 해먹는 사람**. 실패도 해봤고 그래서 요령을 안다.
  - 말투는 **편한 반말**. 친구한테 알려주듯. `ㄷㄷ / ㅠㅠ / ;; / ㅋㅋ` 자연스럽게.
  - "제가 해봤는데요" 같은 존댓말·블로그체 **금지**. 훈계·설명충 톤 금지.
  - 자기 경험을 깔고 간다 — "나도 처음엔 다 태웠음", "이거 알기 전엔 맨날 실패했음".
  - **하지 않는 말**: 의학적 단정, 다이어트 효능 보장, 제품 과장(§6).
- **컨셉**: **"혹할 만한" 레시피 큐레이션** — 계절·시즌 / 다이어트 / 간단요리 / 연예인 레시피를
  **한 장짜리 1:1 인포그래픽**으로 만들어 저장·공유를 유도하고, 댓글의 쿠팡 제휴링크로 수익화.
- **수익 원리**: 쿠팡파트너스 **라스트클릭 24시간** — 링크 클릭 수가 곧 수익.
  레시피 글은 **저장률이 높아** 댓글 링크 노출이 오래 간다.

## 2. 주제 규칙 (가장 중요)

레시피 **자체**가 아니라 **주제 프레이밍**이 후킹이다. 아래 유형으로만 뽑는다.

| 유형 | 예시 |
|---|---|
| 권위 추천형 | 의사가 추천하는 아침식사 TOP3 / 한의사가 겨울에 꼭 먹으라는 국 3가지 |
| 상황 해결형 | 아이 등교 전 10분 아침밥 5가지 / 자취 첫 주에 살아남는 한그릇 |
| 체질·증상형 | 손발 차가운 사람 한그릇 뚝딱 레시피 / 붓기 빠지는 아침 국 |
| N가지 묶음형 | 계란샌드위치 6가지 / 마시면 살 빠지는 겨울차 6가지 |
| 시즌·계절형 | 여름 입맛 없을 때 냉국 4가지 / 김장철 남은 배추 활용 3가지 |
| 다이어트형 | 밥 대신 먹는 200kcal 한끼 5가지 |
| 연예인 레시피형 | ○○이 방송에서 알려준 5분 요리 |

**규칙**
- 제목에 **숫자**(TOP3 / 6가지 / 10분 / 200kcal)를 반드시 넣는다. 스크롤을 멈추는 건 숫자다.
- **N가지 묶음형이면 이미지 한 장에 N개 레시피가 전부 담기고, 각각 완성 사진이 들어가야 한다.**
- 연예인 레시피는 **"방송에서 공개된"** 등 출처가 실재하는 것만. 추측·창작 금지(§6).

## 3. 콘텐츠 포맷 (확정)

한 세트 = **본문(1/2) + 댓글(2/2)** 2개 스레드(자기답글).

### 📐 포맷은 반드시 섞는다 (중요)

묶음형("○○ 6가지")만 계속 나가면 지루해진다. **두 포맷을 섞어서** 발행한다.

| 포맷 | 레이아웃 키 | 카드 구성 | items 의미 |
|---|---|---|---|
| **묶음형** | `grid2x2` `grid2x3` `rank3` | N개 요리를 격자/순위로 | (메뉴명, 한 줄 조리법) |
| **단일 레시피 상세형** | `single` | 요리 **1개**를 깊게 — 큰 완성컷 + 재료 컷아웃 + 조리 단계 | (조리 단계명, 설명) |

- 비율: **묶음형 약 3 : 단일형 1**. `topics_spec.py` 에서 3~4건마다 단일형이 끼도록 배치.
- 단일형 제목은 요리 이름 + 후킹 (예: "안 터지는 계란말이", "돼지고기 김치찌개 황금비율").
- 단일형 본문 머리말은 `📌 {제목} 만드는 법`, 묶음형은 `📌 {제목}`.

### 이미지 — 1:1 인포그래픽 **1장**
- **1080 × 1080 (1:1)**, PNG.
- **한 장 안에 전부 담긴다**: ①제목(숫자 포함) ②완성 요리 사진 ③재료 ④레시피 순서.
- **손글씨(펜) 요소 필수** — 제목 또는 라벨·주석·화살표를 손글씨체로. 폰트: `Gaegu` / `NanumPenScript`.
- 톤: 따뜻한 크림/아이보리 종이 배경, 에디토리얼 잡지 레이아웃, 여백 넉넉히.
- **가독성 우선** — 최소 본문 26px @1080 기준. 글자가 사진 위에 겹쳐 뭉개지면 실패.
- 레퍼런스 무드: 크림 배경 + 재료 컷아웃 + 얇은 구분선 + 손글씨 라벨.

### 🔥 후킹 규칙 (조회수 = 이걸로 갈린다)

스레드는 **첫 1~2줄만 미리보기로 뜬다.** 거기서 안 멈추면 그 글은 죽는다.
그리고 **답글이 노출을 밀어준다** — 저장·좋아요보다 댓글이 세다.

**① 첫 줄 = 스크롤 스토퍼.** 아래 중 하나로 연다.

| 유형 | 원리 | 예 |
|---|---|---|
| 의외성·충격 | 상식을 깬다 | 만두랑 토마토소스가 이렇게 어울릴 줄 몰랐어;; |
| 실패 고백 | 공감 + 신뢰 | 이거 알기 전엔 계란말이 맨날 부서졌음ㅠㅠ |
| 손해 프레임 | FOMO | 이거 모르고 산 사람 진짜 손해임ㄷㄷ |
| 숫자 단언 | 구체성 | 재료 3개로 5분이면 끝남 |
| 상황 저격 | "내 얘기네" | 밤에 라면은 좀 그럴 때 있잖아;; |
| 비용 비교 | 이득 | 사 먹으면 8천원인데 집에서 2천원 |

**금지**: "오늘은 ○○를 소개할게요" 류 예고편, 뻔한 인사, 존댓말.

**② 마무리 = 댓글 유도 → 재료 안내** (순서 고정)
```
{팁 — 실패 포인트 1~2개}

{댓글 유도 질문}      ← 답하기 쉬운 것. CTAS 풀에서 슬러그 해시로 자동 선택
👇재료는 댓글에 적어뒀어
```
댓글 유도는 **답하기 쉬워야** 한다. "너네는 뭐 해먹어?" > "의견 남겨주세요".
`build_recipe_queue.py` 의 `CTAS` 가 10종을 돌려쓴다(같은 글엔 항상 같은 문구).

**③ 레시피는 진짜 레시피여야 한다.**
메뉴 나열은 저장이 안 된다. **계량·온도·시간**을 넣는다.
(❌ "만두 구워서 치즈 올리기" / ⭕ "냉동만두 10개, 에어프라이어 180도 12분")

### 본문 (1/2) — 최대 500자
```
{후킹 1~2줄, 반말+이모지}

📌 {레시피명}
1. …
2. …
3. …

{한줄 마무리 + 저장 유도}
재료는 댓글에 적어둘게!
```
- 레시피는 **간략하게**. 번호 매긴 3~6줄, 한 줄 25자 이내.
- N가지 묶음형이면 각 항목을 `1. 이름 — 핵심 한 줄` 로 압축.
- `ㄷㄷ / ㅠㅠ / ;; / ㅋㅋ` 활용. 존댓말 금지(계정 톤 = 반말).

### 댓글 (2/2) — 텍스트만, 최대 500자
```
[광고] 재료 정리해둘게!

📍재료
• …
• …

🔽'{대표재료 상품명}' 정보는 아래에🔽

이 포스팅은 쿠팡 파트너스 활동의 일환으로, 이에 따른 일정액의 수수료를 제공받습니다.
{쿠팡 링크}
{쿠팡 링크}        ← 링크 2번 반복
```

### ⚠️ 절대 조건 — 댓글에 링크 **썸네일 카드**가 떠야 한다

댓글의 쿠팡 링크에는 스레드가 자동 생성하는 **미리보기 썸네일 카드**(상품 이미지 + 제목 +
link.coupang.com)가 반드시 붙어야 한다. **카드가 안 뜨면 클릭이 안 나고 수수료를 못 받는다.**

**실측(2026-08-25)**: 발행된 쿠팡 링크 댓글 18건 전수 조회 결과 **18/18 카드 정상**.
그 18건은 전부 링크 뒤에 공정위 문구가 오는 형태였다 →
**링크의 위치·순서는 썸네일과 무관하다.** 순서를 강제하지 않는다.

카드를 결정하는 진짜 조건은 **링크가 살아 있어 스레드가 미리보기를 뽑아낼 수 있는가**다.
따라서 순서 규칙 대신 **발행 후 실측 검증**으로 보장한다:

- `publish_recipe.py` 는 답글 발행 직후 `link_attachment_url` 을 최대 6회 폴링해
  카드 부착을 확인하고, 안 붙었으면 **경고를 찍고 워크플로를 실패 처리**한다
  (큐 커밋은 `if: always()` 로 별도 수행 → 같은 글 재발행 방지).
- `.github/workflows/threads-inspect.yml` (수동) 로 과거 게시물의 카드 부착을 전수 점검할 수 있다.

- **대표 재료 1개**만 링크(예: 계란샌드위치 → "1등급 계란"). 링크는 **2번 반복**.
- 재료가 많으면 핵심만 남기고 자른다(500자 초과 금지).
- **공정위 대가성 문구 필수**(표준 문구 그대로). 위치는 자유.
- 댓글에는 **사진 없음**(썸네일은 링크로 자동 생성되는 것).

## 4. 이미지 제작 파이프라인 (확정)

**엔진 = codex-image 스킬** (`~/.claude/skills/codex-image/scripts/gen.sh`), **square 1080×1080 · 1콜 완결**.

> 실측(2026-08-25): codex 이미지 도구는 **한글 제목·라벨·손글씨 주석을 정확히 렌더**한다.
> 별도 HTML 합성 없이 **한 번의 호출로 인포그래픽 전체를 생성**하는 것으로 확정.

호출은 `gen_card.sh` 래퍼가 담당하며, 아래 **고정 스타일 블록**을 프롬프트에 항상 덧붙인다.

```
Korean recipe infographic poster, square 1:1.
Title in large Korean Hangul reading '{제목}'.
{본문 레이아웃 지시 — N개 카드 그리드 / 재료 컷아웃 / 순서 스텝 등}
Warm cream paper background, clean editorial magazine layout, generous whitespace,
handwritten Korean pen-style annotations with hand-drawn arrows,
soft natural food photography, high legibility, no watermark, no logo.
```

**레이아웃 3종(주제 유형별로 골라 씀)**
| 레이아웃 | 쓰는 주제 | 지시문 요지 |
|---|---|---|
| `grid` | N가지 묶음형 | `N labeled photo cards in a {r}x{c} grid, each with a short Korean caption` |
| `single` | 단일 레시피 | 상단 완성컷 1장 + 좌측 재료 컷아웃 리스트 + 하단 4스텝 |
| `rank` | TOP3 권위 추천형 | 1·2·3 순위 뱃지 + 각 완성컷 + 한 줄 코멘트 |

**검수 체크리스트(사람이 눈으로 1회)**
- [ ] 한글 자모가 깨지거나 없는 글자가 없는가
- [ ] 제목에 숫자가 들어갔는가
- [ ] N가지 묶음이면 **N개가 정확히** 다 들어갔는가
- [ ] 글자가 사진에 묻혀 안 읽히는 곳이 없는가
- [ ] 손글씨 요소가 있는가

깨졌으면 프롬프트를 고쳐 **재생성**한다(1콜 ≈ 24k 토큰 · 30~60초).
산출물: `recipe/cards/<slug>.png` → 검수 통과분만 `recipe/images/<slug>.png` 로 승격·커밋.

## 5. 이미지 호스팅 (자동 발행의 핵심)

Threads API는 **공개 URL**만 받는다. 힉스필드 CDN 대신 **레포 자체를 호스팅으로 쓴다**:

1. 완성 PNG를 `recipe/images/<slug>.png` 로 커밋·푸시.
2. URL = `https://raw.githubusercontent.com/scalemaker-ship-it/bbangjjioo-threads/main/recipe/images/<slug>.png`
3. 이 URL을 `recipe_queue.json` 의 `images[0]` 에 넣는다.

⚠️ 레포가 **public** 이어야 한다. private이면 raw URL에 토큰이 붙어 Threads가 못 읽는다.

## 6. 컴플라이언스

- **공정위 대가성 표시**: 표준 문구 필수(위치 자유).
- **광고 라벨**: 댓글 첫 줄 `[광고]`.
- **효능 단정 금지**: "살 빠진다 / 붓기 빠진다 / 낫는다 / 100%" 류 **단정 금지**.
  → "도움 된다더라 / 개운하더라 / 속이 편하더라" 체감·전언 톤으로 순화.
  ※ 주제 제목의 "마시면 살 빠지는"류도 → "다이어트할 때 마시는" 으로 바꿔 쓴다.
- **의학적 조언 금지**: "의사가 추천하는"은 실제 널리 알려진 권고 범위 내에서만.
- 남의 레시피·사진·문장 **복붙 금지**. 참고는 영감까지, 글은 원본 작성.
- 연예인 레시피: 실제 방송·인터뷰에서 공개된 것만. **없는 발언 창작 금지.**

## 8. 발행 스케줄

**하루 3회.** 각 슬롯마다 0~50분 랜덤 지연.

| 슬롯 | KST | UTC 크론 |
|---|---|---|
| 오전 | 11:00~11:50 | `0 2 * * *` |
| 오후 | 15:00~15:50 | `0 6 * * *` |
| 저녁 | 18:00~18:50 | `0 9 * * *` |

요일주제(07시)와 겹치지 않는다. 지연 상한이 50분인 이유: 60분이면 저녁 슬롯이 19시를 넘긴다.
큐가 비면 조용히 종료(정상).

⚠️ **소진 속도 = 하루 3건 = 한 달에 90건.** 큐 잔량 확인:
```bash
python3 -c "import json;print(len(json.load(open('recipe/recipe_queue.json'))['items']))"
```

## 9. 제작 흐름 (대량 생산 기준)

1. **주제 스펙 작성** — `topics_spec.py` 에 항목 추가.
   `(slug, 제목, 레이아웃, items, 후킹, 마무리팁, [재료줄], 제품키)`.
   포맷을 섞을 것(§3). 제목에 숫자 필수(§2).
2. **대표재료 카탈로그** — 새 제품키가 필요하면 `keywords.txt` 에 추가 후
   `gh workflow run recipe-products.yml` (이미 있는 키는 안 건드림).
3. **프롬프트·텍스트 생성** — `python3 build_recipe_queue.py prompts && ... texts`.
   500자 초과가 있으면 스펙을 줄인다.
4. **카드 대량 생성** — `./gen_worker.sh fwd 3 &`, `./gen_worker.sh rev 3 &` 등 병렬로.
   워커는 이미 있는 카드를 건너뛰므로 여러 개 띄워도 안전.
   ⚠️ 초반엔 빠르다가 **레이트리밋으로 느려진다**(3워커 기준 5분에 9장).
5. **검수** — §4 체크리스트. 통과분을 `cards/` → `images/` 로 이동.
6. **큐 적재** — `python3 build_recipe_queue.py queue` (images/ 에 있는 것만 담는다).
7. **링크 점검** — `python3 check_links.py` 로 딥링크 전수 확인.
8. **커밋·푸시** — 이미지가 푸시돼야 raw URL 이 산다.
9. 크론이 하루 3회 자동 발행 + 썸네일 검증.
